## Known Limitations
- The live registration endpoint may return `ALREADY_REGISTERED`, confirming the service was already registered at the requested version. Subsequent steps succeeded.
- **Replay**: The deployed QCG replay lineage endpoint (`/qcg/replay/lineage/{trace_id}`) returns 404. The current `PlatformReplayAdapter` is missing the `submit()` method. Existing replay evidence was generated by the local stub `CanonicalReplayAuthority`, not the canonical QCG replay authority.
- **Telemetry**: `TraceStore` is imported unconditionally from `src/platform/stubs.py`. No live telemetry backend is configured or reachable. Telemetry evidence represents local stub return values, not live exports.

## Dependencies
- **Platform-side Manifest**: The deployed Platform HTTP registration handler does not currently forward a manifest into the underlying registry registration call. Service metadata exists and the manifest field can be null in metadata. This is a Platform-side dependency.
- **Platform-side Replay**: QCG replay lineage endpoint must be exposed and functional.
- **Platform-side Telemetry**: Canonical telemetry ingestion endpoint and contract must be published.

## Remaining External Actions
1. QCG owner must expose canonical replay lineage/submission endpoints and notify Insight Stack of the contract.
2. Telemetry owner must publish the participant-facing telemetry ingestion contract.
3. Platform team must resolve manifest forwarding limitation.

## Final Assessment
Insight-side live runtime integration is verified for registration, discovery, version negotiation, execution, and evidence generation. Replay certification and live telemetry integration are blocked by external dependencies. The repository is structurally sound but not fully locked. Final platform-wide production certification remains dependent on external platform/governance requirements.
